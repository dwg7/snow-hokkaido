# 3. AIの活用方法

このプロジェクトの多くのコードと文書は、**AI (Claude Code) と人間がいっしょに**作りました。どう分担し、どこに気をつけたかを、正直に書きます。

## 役割分担

| | 人間 | AI (Claude Code) |
|---|---|---|
| 問いを決める | ○ 「雪が増える様子を見たい」 | |
| 大きな設計を決める | ○ セルの大きさ、使う衛星、「見えなかったことも記録する」方針 | 選択肢と理由を出す |
| プログラムを書く | | ○ |
| データを調べる | | ○ 実際に取りに行って、結果を確かめる |
| テストを書いて動かす | | ○ |
| 結果が正しいか判断する | ○ 最後は人間 | 疑わしい点を指摘する |
| 公開してよいか決める | ○ | |

AI は「作業が速い助手」で、**何を作るか**と**どこまで信じるか**は人間が決めます。

## 作業の進め方

1. **設計メモを先に渡す。** 最初に、考え方・決めたこと・まだ決めていないことを書いた文書([CLAUDE.md](../CLAUDE.md))を AI に渡しました。AI はこれを読んでから作業します。
2. **小さい段階に分ける。** 「まず1枚の写真で、最後まで通す」という小さな目標から始め、1段階ずつ確かめました。
3. **わからないことは「未確認」と書く。** 調べていないことを、調べたことにしない約束です。README の「わかっていないこと」は、この約束の結果です。
4. **別の AI の知恵も借りる。** 同じ人が、他のプロジェクトで AI と見つけたコツをまとめた公開リポジトリ(cafebabe)があります。計器盤まわりの経験は、そこから教わりました。ただし、**教わったことも、自分で確かめてから使いました**(古い情報や、条件のちがう情報かもしれないからです)。

## AI がまちがえかけた例 (そして、どう気づいたか)

AI は自信ありげに間違えることがあります。だから、**検算できる形**にしておくことが大事でした。

### 例1: 数値の補正をまちがえた
衛星画像の説明データには「値から 0.1 を引いて使う」と書いてありました。そのとおりに計算すると、10月中旬の大雪山の**71%が雪**になりました。ところが、衛星自身の分類ラベル(SCL)では、雪は約1〜2%です。**2つの方法の答えが大きく食いちがう**ので、おかしいと気づけました。

そこで、同じ撮影の画像を、2つの置き場(古い版と新しい版)から取って、画素の値を比べました。すると、新しい版は古い版より**ちょうど1000だけ大きく**、その分(0.1)を引く情報が、新しい版のファイルの中にだけ入っていました。古い版は、すでに引いてある状態だったのです。説明データは、どちらの版にも「0.1を引く」と書いていたので、古い版では二重に引いていたことになります。

直し方は、説明データではなく、**画像ファイル自身の情報を読む**ことにしました。直したあとは、2つの版で雪の判定が一致しました。ただし、確かめたのは1シーン・1か所だけで、ほかの時期のデータは未確認です。

> 学び: 1つの方法の答えだけを信じず、**別の方法と突きあわせる**。説明書より、現物を確かめる。

### 例2: 使うつもりのデータに必要な情報がなかった
市町村の境界は、最初に使うつもりの地理院のデータ(AdmArea)を調べました。ところが、市町村の番号(コード)が入っておらず、どの市町村か特定できませんでした。そこで、番号つきの国土数値情報に切りかえました。**使う前に中身を調べた**から、あとで困らずに済みました。

### 例3: 地図が真っ黒になった
地図の上に重ねた雪の画像が、真っ黒に表示されました。画像ファイルは正しかったので、原因探しをして、表示の設定の1つ(`nearest`)をやめると直ることがわかりました。ただし、**なぜそうなるのかは未確認**です(確認に使ったのは1種類のブラウザだけです)。コードには、その旨をコメントとして残しています。

> 学び: 「直った」と「理由がわかった」は別。わからないことは、わからないと書き残す。

## AIとの仕事で、気をつけたこと

- **公開リポジトリなので、書いてよい内容を決めた。** 個人情報、大きな生データ、私的なリンクは入れない([CLAUDE.md](../CLAUDE.md) に方針を書きました)。AI に渡す前にも、この区別を意識します。
- **自動テストで守る。** 「数の足し算が合う」などの約束を、テストにしました(`just test`)。AI が書き換えても、テストが通るか確認できます。
- **取りに行ったデータは、出典とバージョンを記録する。** 例: 取り込んだ部品の取得元とコミット番号を `docs/vendor/tabularmap/SOURCE.txt` に残しました。
- **変更は、人間が見て判断する。** AI が出した結果は、そのまま「正しい」とせず、数字の筋が通っているかを見ます。
- **AI が書いた文章にも、同じ基準を。** この文書も AI が下書きしました。事実とちがうところがあれば、直してください。

## あなたが試すなら

- 「このコードは何をしているの?」と AI に聞いてみる。説明が正しいか、実際に動かして確かめる。
- AI の答えと、別の資料(論文、公式の説明、実際のデータ)を見比べる。
- 「どうしてそう思うの?」「ほかの確かめ方は?」と聞く。**自分で検算できる形**に直してもらう。
- 動いたあとで、**どんな場面で壊れそうか**を、いっしょに考える。

AI は強力な道具ですが、**問いを持つのは人間**です。このプロジェクトも「雪が増える様子を見たい」という、ひとりの人間の問いから始まりました。
